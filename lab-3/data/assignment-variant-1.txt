Лабораторная работа 3
Работа предлагается в двух вариантах. Вариант выбирают студенты самостоятельно. Во втором варианте есть возможность получить бонусные 5 баллов.
“RAG-поиск по корпусу научных публикаций”
Спроектировать и реализовать конвейер генерации с расширенным поиском (Retrieval-Augmented Generation, RAG) для базы научных статей: от сбора данных и индексации до векторизации, семантического поиска, генерации аргументированного ответа с указанием источников и измеримой оценки качества.


Вариант 1
Задание:
1. Сбор корпуса документов
* Выбрать предметную область (например, Retrieval-Augmented Generation, Computer Vision for Autonomous Driving, Efficient Transformers).
* Собрать корпус минимум из 300 статей (название, авторы, год, аннотация, ссылка).
* Можно взять корпус из первого задания, если он подходит по количеству. Или собрать одним из двух способов:
   * OpenAlex API (рекомендуется для стабильной работы без блокировок по IP): фильтрация по теме и источнику arXiv https://api.openalex.org/works.
   * arXiv API (через официальную библиотеку arxiv или локальный XML-дамп).
* Сохранить метаданные и тексты в структурированном виде (Pandas DataFrame или JSON Lines).
2. Препроцессинг и стратегия чанкинга (Chunking)
* Объединить название статьи и её аннотацию в единый документ для сохранения контекста.
* Реализовать разбиение длинных аннотаций/текстов на смысловые фрагменты. Параметры разбиения: размер чанка 120–150 слов (или 500–700 символов / ~150–200 токенов), перекрытие (Overlap): 20–30 слов (или ~100 символов). Параметры можно скорректировать.
* Реализовать чанкинг двумя способами:
   * На чистом Python (скользящее окно по предложениям/словам);
   * С использованием RecursiveCharacterTextSplitter (LangChain).
* К каждому чанку привязать метаданные родительской статьи (doc_idTitle, Authors, URL).
3. Векторизация и индекс (Vector Store)
* Инициализировать легковесную модель для построения эмбеддингов предложений (например, sentence-transformers/all-MiniLM-L6-v2 или BAAI/bge-small-en-v1.5).
Следующие пункты надо сделать для каждого способа чанкинга по отдельности.
* Перевести все чанки в плотные векторы (Embeddings). 
* Построить векторный индекс с использованием FAISS (например, IndexFlatIP с предварительной L2-нормализацией векторов для косинусного сходства или IndexFlatL2).
* Реализовать функцию retrieve(query: str, top_k), возвращающую top_k наиболее релевантных фрагментов с оценками сходства (similarity scores).
4. Обработка пользовательских запросов. 
Пользовательский ввод может содержать случайные искажения. Реализовать пайплайн очистки запроса:
* Проверка и коррекция опечаток с использованием SymSpell или rapidfuzz (с осторожностью к аббревиатурам и научным терминам);
* Формирование чистого поискового запроса для поиска по индексу.
5. Интеграция с LLM и промпт-инжиниринг
* Настроить компактную LLM для синтеза ответа по найденному контексту:
   1. Локально в Colab/ноутбуке (например, Qwen/Qwen2.5-1.5B-Instruct, meta-llama/Llama-3.2-1B-Instruct через transformers / bitsandbytes 4-bit);
   2. Либо через API (OpenAI GPT-4o-mini, Mistral API, Groq, DeepSeek).
* Требования к промпту:
   1. Модель должна отвечать строго на основе предоставленного контекста;
   2. Если в контексте нет ответа, модель обязана явно заявить: «Информация в найденных статьях отсутствует»;
   3. Модель должна указывать ссылки/названия статей, на основе которых сформулирован вывод (Grounding / Citations).
* Составить 5 различных сценариев запросов:
   1. Фактический вопрос по методикам;
   2. Сравнительный анализ двух подходов;
   3. Запрос с опечатками;
   4. Запрос, на который в корпусе нет ответа (проверка на галлюцинации);
   5. Обобщающий запрос (Summarization) по ключевым трендам в собранных статьях.
* Наглядно продемонстрировать разницу: ответ без контекста (чистая LLM) vs ответ с RAG (LLM + контекст из базы).
Критерии оценки:
1. Корректный сбор корпуса (не менее 300 статей), надежная обработка сетевых запросов без сбоев и падений, структурированное сохранение метаданных. (4 балла).
2. Разбиение на чанки: адекватный выбор размера окна и перекрытия под длину аннотаций, связка каждого чанка с родительскими метаданными (ID, заголовок, авторы). (5 баллов).
3. Векторизация: Корректная генерация эмбеддингов, нормализация векторов, построение индекса FAISS и расчет метрик сходства (Top-k Retrieval). (6 баллов).
4. Пайплайн обработки пользовательского ввода, защита от опечаток без искажения научных терминов, корректная фильтрация. (4 балла)
5. Интеграция LLM: качество системного промпта, жесткое следование контексту, цитирование источников, отсутствие галлюцинаций. (6 баллов).
6. Демонстрация 5 тестовых сценариев; наглядное сопоставление ответов «LLM без контекста» и «RAG-конвейер» с анализом точности. (5 баллов).
